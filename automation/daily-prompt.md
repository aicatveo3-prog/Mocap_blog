# 매일 실행 지시서 (품질 우선판)

이 파일은 매일 예약 실행되는 Claude Code 세션이 그대로 따르는 작업 지시서다.
글의 주제·톤·구조·리서치 방법을 바꾸려면 이 파일만 수정하면 된다.

⚠️ **핵심 원칙: 사이트에 바로 발행하지 않는다.** 초안 브랜치(`draft/...`)만 만들어 push 하면
GitHub Actions가 PR을 만들고 텔레그램으로 알림을 보낸다. 사람이 PR을 **병합해야만** 발행된다.

---

## 0. 독자와 톤

- **독자**: AI·테크에 관심 있는 **크리에이터/일반 테크팬** (전문 개발자 아님 기준).
- **톤**: 쉽고 친근하지만 **알맹이 있게**. 전문용어는 반드시 풀어서 설명. 실용적 시사점 중심.
- 어려운 개념도 "이게 왜 나한테 중요한지"가 느껴지게 쓴다.

## 1. 목표

매일 AI 모션캡쳐 관련 **서로 다른 최신 주제 2개**를 찾아, 각 **1,500~2,500자**의
깊이 있는 한국어 글 2편을 **초안**으로 작성한다. (표면 요약 금지 — 아래 규칙 준수)

## 2. 리서치 절차 (원문 기반 — 매우 중요)

검색 결과의 "미리보기"만 보고 쓰지 말 것. 실제로 원문을 열어 읽고 쓴다.

1. **넓게 수집**: 웹 검색으로 후보 주제를 **4~6개** 모은다.
2. **선별**: 참신성·중요도·독자 관심도로 **상위 2개**를 고른다.
   - `_posts/`의 기존 글 제목, 그리고 이미 다룬 **도구·논문·개념**과도 겹치지 않게 한다.
3. **심층 확인**: 고른 주제는 **원문 링크를 실제로 열어(WebFetch) 읽고** 핵심 사실을 파악한다.
4. **교차검증**: 핵심 주장은 **독립된 출처 2개 이상**으로 확인한다.
5. **출처 우선순위**: arxiv·공식 블로그(회사/연구소)·학회·신뢰 매체 > 일반 뉴스.
   콘텐츠팜·SEO 스팸·광고성 글은 배제한다.
6. **최신성**: 가능한 한 최근 자료를 쓴다. 오래된 내용을 "최신"인 것처럼 쓰지 않는다.

## 3. 글 구조 (이 템플릿을 따른다)

- **제목**: 구체적이고 호기심을 부르되 **낚시·과장 금지**.
- **맨 위 3줄 요약(TL;DR)**: 이 글의 핵심을 3줄로. (본문 첫 부분에 배치)
- **본문** (## 소제목으로 나눈다):
  - **무슨 일인가** — 핵심 사실을 정확히
  - **왜 중요한가** — 맥락·의미·파급 (표면 요약이 아니라 여기서 관점을 보여준다)
  - **어떻게 작동/써보나** — 실용 정보 (독자가 실제로 해볼 수 있게)
  - **한계·주의점** — 과장 없이 솔직하게
- **마무리**: 시사점 한 단락. "결론적으로/정리하자면" 같은 뻔한 마무리 금지.

## 4. 문장·스타일 규칙

- 전문용어는 **첫 등장 시 괄호로 짧게 설명** (예: 마커리스(마커 없이 촬영)).
- 능동태, 짧고 명료한 문장. 한 문단은 3~5문장.
- **근거 없는 단정 금지.** 불확실하면 "~로 알려졌다 / ~로 전망된다"로 표기.
- **확인된 사실**과 **전망·의견**을 구분해서 쓴다.
- 비교가 유용하면 **표**를 쓴다(정보 밀도↑).

### 가독성 규칙 (스캔하기 쉽게, 쉽고 자세하게)
- **소제목을 자주 나눈다** — 한 소제목당 3~6문장 정도로 짧게, 스크롤하며 훑어도 흐름이 보이게.
- **불릿·번호목록을 적극 활용**한다(줄글 덩어리 금지).
- 가능하면 **"실제 사용 예시" 1개**를 넣는다(입력 → 결과까지의 흐름을 단계로).
- 어려운 개념은 **일상적인 비유**로 풀어 설명한다(예: 확산 모델 = 안개에서 상을 다듬기).
- 여러 방법을 다룰 땐 **비교표**로 한눈에 정리한다.

## 5. 금지 목록

- 지어내기(환각), 확인 안 된 수치·인용
- 동어반복, 뻔한 마무리, 과장·낚시 제목
- 원문 안 읽고 검색 스니펫만으로 쓰기

## 6. 품질 자기점검 (발행 전 반드시 수행)

초안을 쓴 뒤, **스스로 아래를 냉정하게 점검하고 부족하면 고쳐 다시 쓴다.**
한 항목이라도 미달이면 수정 후 다시 점검한다.

- [ ] TL;DR 3줄이 핵심을 제대로 담는가
- [ ] 표면 요약이 아니라 "왜 중요한가 / 시사점"이 분명한가
- [ ] 모든 핵심 사실에 출처가 있고, **원문을 실제로 확인**했는가
- [ ] 전문용어를 일반 독자가 이해할 수 있게 풀었는가
- [ ] 뻔한 표현·동어반복·과장이 없는가
- [ ] **1,500자 이상**, 깊이가 충분한가
- [ ] 두 글의 주제가 서로 충분히 다른가

## 7. 파일 형식

각 글을 `_posts/YYYY-MM-DD-슬러그.md`로 저장한다. front matter:

```
---
layout: post
title: "한국어 제목(구체적, 낚시 금지)"
date: 2026-07-04 09:00:00 +0900
description: "한 줄 요약(리스트에 노출됨, 80자 이내)"
categories: ["기술"]
tags: ["ai", "motion-capture", "키워드"]
sources:
  - "https://실제로-읽은-원문1"
  - "https://실제로-읽은-원문2"
---

**TL;DR**
- 핵심 1
- 핵심 2
- 핵심 3

## 무슨 일인가
...
```

- 슬러그는 영문 소문자·하이픈만. `date`는 한국시간(+0900) 기준 오늘 날짜.
- `sources`에는 **실제로 열어 읽은** URL만 2~5개.

## 8. 발행 절차 (초안만! 발행 금지)

base 브랜치에서 새 초안 브랜치를 만들어 그 브랜치에만 push 한다.

```
git checkout -b draft/$(date +%Y-%m-%d-%H%M)
git add _posts
git commit -m "draft: 자동 생성 글 ($(date +%Y-%m-%d))"
git push -u origin draft/$(date +%Y-%m-%d-%H%M)
```

- base(발행) 브랜치에는 **직접 push 하지 않는다.**
- PR을 **직접 병합하지 않는다.** (사람이 검토·승인)
- 초안 브랜치가 push되면 끝. PR 생성·텔레그램 알림은 GitHub Actions가 자동 처리한다.
